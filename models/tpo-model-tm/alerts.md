# Alerts

The TPO Model includes a built-in alert engine that monitors value-area interactions, resting historical levels, and higher-timeframe market structure shifts in real time.

Alerts are emitted dynamically using TradingView's `alert()` function rather than static `alertcondition()` blocks. This means you only need to create **a single alert** in TradingView to monitor every level, sweep, and structure transition across the entire indicator.

### Available Alert Types

* Reach Prev POC
* Reach Prev VAH
* Reach Prev VAL
* Acceptance outside VA
* Rejection from VAH/VAL
* Rejection from POC
* Reach nPOC
* CISD Forming (pending)
* CISD Confirmed

### Setting Up an Alert

1. Add the TPO Model to your chart and configure your preferences in the **Alerts** group.
2. Open TradingView's **Alerts** panel (the clock icon on the right toolbar) and click **Create Alert**.
3. Set **Condition** to `CandelaCharts - TPO Model`.
4. Directly below the condition, select **Any alert() function call**.
5. Leave the TradingView frequency setting untouched. The script manages trigger frequencies internally for each alert family (firing once per bar for intrabar touches, and once per bar close for confirmed events).
6. Optional: Paste your webhook URL if forwarding to an external bot, or configure sound and mobile push notifications.
7. Click **Create**.

{% hint style="info" %}
Never select a specific variable or individual input from TradingView's condition dropdown. The script dispatches dynamic `alert()` messages, so selecting anything other than **Any alert() function call** will prevent alerts from triggering.
{% endhint %}

### Message Anatomy

Every alert emitted by the model generates a standardized, single-line message:

```
TICKER · TIMEFRAME · MARKET TYPE · TIMESTAMP · PRICE LEVEL — MESSAGE
```

#### Exact Message Fields

* **Ticker** (`syminfo.ticker`) — The traded instrument symbol (e.g., `ES1!`, `NQ1!`, `BTCUSDT.P`).
* **Timeframe** — For profile reaches, acceptance, rejection, and naked POCs, this displays the execution chart timeframe formatted via the script's `format_tf` engine (e.g., `5m`, `15m`, `1H`). For market structure alerts, this displays the higher timeframe that generated the shift (e.g., `1H`, `4H`, `1D`), or merged timeframes if multiple HTFs swept and broke the same price level (e.g., `1H/4H`).
* **Market Type** (`syminfo.type`) — TradingView instrument classification (`futures`, `stock`, `crypto`, `forex`, `index`).
* **Timestamp** — The current bar's scheduled close time formatted in the exchange's native timezone (`dd MMM yyyy HH:mm <timezone>`).
* **Price Level** — The exact numerical price where the event occurred, formatted to the symbol's minimum tick precision (`str.tostring(level, format.mintick)`).
* **Message** — The plain-English event description generated by the model.

#### Live Output Examples

Level reach on a 5-minute chart:

```
ES1! · 5m · futures · 19 Oct 2026 14:35 America/New_York · 5842.25 — Price reached the 18 Oct session TPO VAH
```

Value Area rejection on a 5-minute chart:

```
ES1! · 5m · futures · 19 Oct 2026 14:40 America/New_York · 5842.25 — Bearish rejection at the 18 Oct session TPO VAH, price closed back inside
```

Naked POC touch on a 15-minute chart:

```
NQ1! · 15m · futures · 19 Oct 2026 15:00 America/New_York · 20385.00 — Price reached the naked TPO POC, untouched since it formed
```

Market structure shift (CISD mode on 1H):

```
NQ1! · 1H · futures · 19 Oct 2026 15:00 America/New_York · 20410.50 — Bullish CISD confirmed on 1H — the sweeping candle closed with the delivery level broken
```

Market structure shift (MSS mode with merged 1H and 4H timeframes):

```
NQ1! · 1H/4H · futures · 19 Oct 2026 16:00 America/New_York · 20410.50 — Bearish MSS confirmed on 1H/4H — the sweeping candle closed with the delivery level broken
```
